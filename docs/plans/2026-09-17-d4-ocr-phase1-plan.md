# D4 OCR Phase 1 — Frame Processor Build Check Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Prove a VisionCamera frame processor runs on a real device on RN 0.81,
before any OCR is wired into it.

**Architecture:** Install VisionCamera 4.7.3 and its worklets runtime in two
separately-verifiable halves — camera preview first (no worklets at all), then
frame processors — so a failure lands on one identifiable cause. No OCR, no
anchor/field logic, no scanner UI beyond what's needed to prove the pipeline runs.

**Tech Stack:** Expo SDK 54 / RN 0.81.5, `react-native-vision-camera@4.7.3`,
`react-native-worklets-core`, expo-dev-client (already installed).

Design reference: `docs/plans/2026-09-17-d4-character-scan-spike-design.md`

## Revised risk assessment — read this before starting

The design doc named "worklets-core alongside Reanimated 4's
`react-native-worklets`" as the top risk. Investigation on 2026-09-17 changed that
picture, and this plan is structured around the new one.

**What was verified:**

| Finding | Evidence |
| --- | --- |
| Reanimated/worklets are unused | No `reanimated`, `useSharedValue`, `useAnimatedStyle`, or `'worklet'` references anywhere in `apps/expo/src/` |
| `expo-router`'s reanimated peer is optional | `peerDependenciesMeta` marks `react-native-reanimated: { optional: true }` |
| NativeWind 5's engine doesn't need it | `react-native-css@3.0.1` peers are react, lightningcss, react-native, @expo/metro-config only |
| Nothing else peers on it | No other workspace package declares it |
| The collision mechanism | `babel-preset-expo@54.0.6` auto-adds `react-native-worklets/plugin` when that package is installed; worklets-core ships a competing plugin claiming the same `'worklet'` directive |

**Conclusion:** removing `react-native-reanimated` and `react-native-worklets`
eliminates the babel plugin collision outright, rather than trying to make two
worklet runtimes coexist. That is Task 1.

**The remaining top risk, which cannot be dissolved this way:**
`react-native-worklets-core@1.6.3` was built against **RN 0.76.1**; this app is on
**RN 0.81.5**. worklets-core installs JSI bindings against React Native internals,
which is exactly the kind of coupling that breaks across five minor versions. If
Phase 1 fails, this is the most likely reason. Task 4 covers what to do about it.

**Forward-looking caveat:** the eventual guided overlay may want animated UI. Once
Reanimated is removed, adding it back re-creates the collision. Prefer React
Native's built-in `Animated` API for overlay work, or revisit this decision
deliberately rather than reflexively re-adding Reanimated.

**Step 3: Create a minimal camera screen — preview only, no frame processor**

Create `apps/expo/src/app/scan.tsx`:

```tsx
import { useEffect } from "react";
import { Text, View } from "react-native";
import { Stack } from "expo-router";
import {
  Camera,
  useCameraDevice,
  useCameraPermission,
} from "react-native-vision-camera";

export default function ScanScreen() {
  const device = useCameraDevice("back");
  const { hasPermission, requestPermission } = useCameraPermission();

  useEffect(() => {
    if (!hasPermission) void requestPermission();
  }, [hasPermission, requestPermission]);

  if (!hasPermission) {
    return (
      <View className="flex-1 items-center justify-center bg-black">
        <Text className="text-white">Camera permission required</Text>
      </View>
    );
  }

  if (device == null) {
    return (
      <View className="flex-1 items-center justify-center bg-black">
        <Text className="text-white">No camera device found</Text>
      </View>
    );
  }

  return (
    <View className="flex-1 bg-black">
      <Stack.Screen options={{ title: "Scan" }} />
      <Camera style={{ flex: 1 }} device={device} isActive={true} />
    </View>
  );
}
```

**Step 4: Rebuild and run**

### Task 3: Add worklets-core and prove a frame processor runs

This is the risky task. Everything before it is now known-good, so a failure here
is attributable.

**Files:**
- Modify: `apps/expo/package.json`
- Create: `apps/expo/babel.config.js`
- Modify: `apps/expo/src/app/scan.tsx`

**Step 1: Install worklets-core**

```bash
cd /home/ytwat/workspace/diablo-4-character-scanner-worktrees/phase0
pnpm add react-native-worklets-core --filter @acme/expo
```

**Step 2: Create a Babel config**

This project currently has **no** `babel.config.js` — it relies on
`babel-preset-expo` defaults. worklets-core's plugin is not auto-detected by that
preset (the preset only auto-adds Reanimated's), so it must be declared.

Create `apps/expo/babel.config.js`:

```js
// react-native-worklets-core ships its own Babel plugin, which babel-preset-expo
// does not auto-detect. Reanimated (whose plugin would collide with this one over
// the 'worklet' directive) was removed in Task 1, so this is the only worklet
// transform in the pipeline.
module.exports = function (api) {
  api.cache(true);
  return {
    presets: ["babel-preset-expo"],
    plugins: ["react-native-worklets-core/plugin"],
  };
};
```

**Step 3: Add a trivial frame processor**

In `apps/expo/src/app/scan.tsx`, import `useFrameProcessor` and add a processor
that only reports frame geometry — no OCR, nothing that could fail for its own
reasons:

```tsx
import {
  Camera,
  useCameraDevice,
  useCameraPermission,
  useFrameProcessor,
} from "react-native-vision-camera";
```

Inside the component, above the return:

```tsx
  const frameProcessor = useFrameProcessor((frame) => {
    "worklet";
    console.log(`frame ${frame.width}x${frame.height} ${frame.pixelFormat}`);
  }, []);
```

And pass it to the camera:

```tsx
      <Camera
        style={{ flex: 1 }}
        device={device}
        isActive={true}
        frameProcessor={frameProcessor}
      />
```

**Step 4: Clear caches and rebuild**

A new Babel plugin requires clearing the Metro cache, or the transform silently
won't apply:

```bash
cd apps/expo
rm -rf node_modules/.cache/metro
ANDROID_HOME=/mnt/d/android/sdk npx expo run:android --device
```

**Step 5: Verify frames actually flow**

With the app on the `/scan` route:

```bash
adb logcat -s ReactNativeJS:V | grep -i "frame "
```

Expected: a stream of `frame 1280x720 yuv` style lines (exact dimensions and
pixel format will vary by device).

This is the Phase 1 pass condition: **frames reaching a worklet on device.**

If it fails, capture the exact failure mode — they need different responses:
- **Build failure** (linker/JSI symbol errors) → worklets-core/RN 0.81 ABI
  mismatch, the predicted risk.
- **Runtime crash on opening `/scan`** → same root cause, surfacing later.
- **Builds and runs but no log lines** → Babel plugin not applied; re-check the
  Metro cache clear and `babel.config.js` location.

Do not try more than one fix at a time, and do not silently downgrade React Native
to make it work — that is a much larger decision than this spike should make
unilaterally.

### Task 4: Record the result and decide

A decision point, not code. Append a `## Phase 1 results` section to
`docs/plans/2026-09-17-d4-character-scan-spike-design.md` covering:

1. Did removing Reanimated break anything at runtime?
2. Did the camera preview work (Task 2)?
3. Did frames reach a worklet (Task 3)? If not, the exact failure mode.
4. Observed frame dimensions and pixel format — these feed Phase 2's ROI cropping
   math and the design doc's latency budget.

**If Task 3 passed:** Phase 2 is unblocked. Write its plan — the local Expo module
at `apps/expo/modules/d4-ocr/` wrapping ML Kit, which is also where the ML Kit
dependency deliberately dropped in Task 0 gets its durable home.

**If Task 3 failed on an ABI/JSI mismatch,** the fallbacks in preference order:

1. **VisionCamera without frame processors** — use `takeSnapshot()` on an interval
   and run OCR on the resulting image. Keeps the camera stack and the ROI/overlay
   architecture; loses true frame-rate processing. Meaningfully better than the
   design doc's original fallback C because expo-camera's `takePictureAsync` is
   slower and shutter-laggy, whereas `takeSnapshot` is a cheap preview grab.
2. **Design doc fallback C** — expo-camera + `@react-native-ml-kit/text-recognition`
   on stills.
3. **Upgrading React Native** to a version worklets-core supports — flag to the
   user as a decision, do not do it unprompted. It affects the whole monorepo.

Note that Phase 0 already proved OCR works on still images, so every fallback here
still yields a working product — the question is only frame rate and how closely
the spike models the eventual live overlay.
