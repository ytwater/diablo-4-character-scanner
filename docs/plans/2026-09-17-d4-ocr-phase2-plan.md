# D4 OCR Phase 2 — Live OCR Pipeline Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Read the character's Name (and Level/Title, best-effort) live off the
camera feed, with a real lock-in UI, closing the loop between Phase 0 (OCR works
on stills) and Phase 1 (frames reach a worklet).

**Architecture:** A local Expo module (`apps/expo/modules/d4-ocr/`) wraps ML Kit
and registers as a VisionCamera Frame Processor Plugin named `scanText`, returning
raw text blocks with bounding boxes on every frame. Pure JS logic downstream
(`apps/expo/src/features/scanner/`) does everything else: fuzzy-match the
`"CHARACTER"` header as a spatial anchor, extract Name/Title/Level by position
relative to it, and lock in a value once it wins a rolling per-field vote. The
scan screen renders live candidates that solidify on lock.

**Tech Stack:** Kotlin (ML Kit Text Recognition, `com.google.mlkit:text-recognition:16.0.1`),
Expo Modules API (`OnCreate` lifecycle to register with VisionCamera's
`FrameProcessorPluginRegistry`), `react-native-vision-camera@4.7.3` frame
processors (already working per Phase 1), Vitest for the pure JS logic.

Design reference: `docs/plans/2026-09-17-d4-character-scan-spike-design.md`
Prior phases: Phase 0 (OCR proven on stills, 93% name hit rate), Phase 1 (frame
processors run live at ~30fps, 640x480)

## What Phase 0 and Phase 1 change about this plan

Read this before starting — it corrects assumptions the original design doc made
before real data existed.

1. **Anchor on the literal string `"CHARACTER"`, not a class vocabulary.** The
   character sheet has no class text anywhere. Confirmed in the design doc's
   revision after reviewing real photos.
2. **Level is best-effort, not a hard gate.** Phase 0: Name/Title hit 93%, Level
   hit only 33% even on ~12MP stills. Don't block anything on Level locking in.
3. **Frame processor frames are 640x480, not 720p.** Smaller than Phase 0's source
   images. Expect Level to read *worse* live than it did in Phase 0, not better.
   `useCameraFormat` should be used to request the highest resolution the device
   offers at an acceptable frame rate — don't accept the VisionCamera default
   silently.
4. **NativeWind 5 preview can silently fail to size a flex container.** Any new
   layout code in `scan.tsx` uses `StyleSheet`, not `className`, following the
   fix already applied there. Don't reintroduce `className` on layout-critical
   views without testing on device.
5. **A config plugin's manifest/Gradle changes need an explicit `expo prebuild`
   run** — `expo run:android` alone won't re-merge them. Every task below that
   touches native config says so explicitly.

```kotlin
package expo.modules.d4ocr

import android.graphics.BitmapFactory
import com.google.android.gms.tasks.Tasks
import com.google.mlkit.vision.common.InputImage
import com.google.mlkit.vision.text.TextRecognition
import com.google.mlkit.vision.text.latin.TextRecognizerOptions
import expo.modules.kotlin.modules.Module
import expo.modules.kotlin.modules.ModuleDefinition
import java.io.File

class D4OcrModule : Module() {
  override fun definition() = ModuleDefinition {
    Name("D4Ocr")

    AsyncFunction("recognizeTextFromUri") { uri: String ->
      val path = uri.removePrefix("file://")
      val bitmap = BitmapFactory.decodeFile(path)
        ?: throw IllegalArgumentException("Could not decode image at $uri")
      val image = InputImage.fromBitmap(bitmap, 0)
      val recognizer = TextRecognition.getClient(TextRecognizerOptions.DEFAULT_OPTIONS)
      val result = Tasks.await(recognizer.process(image))

      result.textBlocks.map { block ->
        val box = block.boundingBox
        mapOf(
          "text" to block.text,
          "frame" to mapOf(
            "x" to (box?.left ?: 0),
            "y" to (box?.top ?: 0),
            "width" to (box?.width() ?: 0),
            "height" to (box?.height() ?: 0),
          ),
        )
      }
    }
  }
}
```

This is the first place in the whole spike that returns **per-block bounding

### Task 2: Register as a VisionCamera frame processor plugin

The risky-in-principle part of this phase, though Phase 1 already proved the
worklets pipeline works — this is "just" wiring a plugin into it.

**Note on a Task 1 bug that does NOT carry over here:** Task 1 found that
returning a raw nested `Map<String, Any>` from an Expo Modules `AsyncFunction`
silently drops nested values (fixed there with typed `Record` classes). That bug
is specific to Expo Modules' reflection-based type converter. VisionCamera's
frame processor bridge is different machinery entirely —
`JSIJNIConversion.cpp`'s `convertJNIObjectToJSIValue` recursively converts nested
`java.util.Map`/`List` by runtime `isInstanceOf` checks, not static reflection.
Plain Kotlin `mapOf(...)` returned from `callback()` should serialize correctly
here. Don't reach for `Record` classes in this task (the `FrameProcessorPlugin`
base class's `callback()` returns plain `Any` — Records aren't part of this
bridge at all) — if empty nested objects show up again, look elsewhere first
(e.g. whether the returned type is a Kotlin data class instead of a plain Map).

```kotlin
package expo.modules.d4ocr

import android.media.Image
import com.google.android.gms.tasks.Tasks
import com.google.mlkit.vision.common.InputImage
import com.google.mlkit.vision.text.TextRecognition
import com.google.mlkit.vision.text.latin.TextRecognizerOptions
import com.mrousavy.camera.core.types.Orientation
import com.mrousavy.camera.frameprocessors.Frame
import com.mrousavy.camera.frameprocessors.FrameProcessorPlugin
import com.mrousavy.camera.frameprocessors.VisionCameraProxy

class D4OcrFrameProcessorPlugin(
  proxy: VisionCameraProxy,
  options: Map<String, Object>?,
) : FrameProcessorPlugin() {
  private val recognizer = TextRecognition.getClient(TextRecognizerOptions.DEFAULT_OPTIONS)

  private fun Orientation.toDegrees(): Int = when (this) {
    Orientation.PORTRAIT -> 0
    Orientation.LANDSCAPE_LEFT -> 90
    Orientation.PORTRAIT_UPSIDE_DOWN -> 180
    Orientation.LANDSCAPE_RIGHT -> 270
  }

  override fun callback(frame: Frame, params: Map<String, Any>?): Any {
    val mediaImage: Image = frame.image
    val rotation = frame.orientation.toDegrees()
    val image = InputImage.fromMediaImage(mediaImage, rotation)
    val result = Tasks.await(recognizer.process(image))

    return result.textBlocks.map { block ->
      val box = block.boundingBox
      mapOf(
        "text" to block.text,
        "frame" to mapOf(
          "x" to (box?.left ?: 0),
          "y" to (box?.top ?: 0),
          "width" to (box?.width() ?: 0),
          "height" to (box?.height() ?: 0),
        ),
      )
    }
  }
}
```

**Important caveat to verify, not assume:** `frame.image` on the `Frame` class in
this VisionCamera version may be named `getImage()` (Java-style, called as
`frame.image` from Kotlin) or may require a different accessor — check the
actual installed version's `Frame.java` at
`node_modules/.pnpm/react-native-vision-camera@4.7.3*/node_modules/react-native-vision-camera/android/src/main/java/com/mrousavy/camera/frameprocessors/Frame.java`
before assuming this compiles. It throws `FrameInvalidError` (a checked-style
exception) — Kotlin will require handling or declaring that.

The rotation-to-degrees mapping above is inferred from
`Orientation.fromRotationDegrees()`'s ranges (see that file in the same
directory) rather than read from an explicit reverse-mapping method. **Verify
this empirically in Task 2's Step 4** — if the recognized text comes back
garbled or the bounding boxes look transposed (width/height swapped) when the
phone is upright, the rotation value is wrong; log `frame.orientation` and try
each of the four values until output looks sane.

// anchor.ts
export interface TextBlock {
  text: string;
  frame: { x: number; y: number; width: number; height: number };
}

const ANCHOR_TEXT = "character";
const MAX_EDIT_DISTANCE = 2; // tolerates 1-2 misread characters, e.g. "CHARACTER G"

function levenshtein(a: string, b: string): number {
  const dp: number[][] = Array.from({ length: a.length + 1 }, () =>
    new Array<number>(b.length + 1).fill(0),
  );
  for (let i = 0; i <= a.length; i++) dp[i]![0] = i;
  for (let j = 0; j <= b.length; j++) dp[0]![j] = j;
  for (let i = 1; i <= a.length; i++) {
    for (let j = 1; j <= b.length; j++) {
      const cost = a[i - 1] === b[j - 1] ? 0 : 1;
      dp[i]![j] = Math.min(
        dp[i - 1]![j]! + 1,
        dp[i]![j - 1]! + 1,
        dp[i - 1]![j - 1]! + cost,
      );
    }
  }
  return dp[a.length]![b.length]!;
}

export function findAnchor(blocks: TextBlock[]): TextBlock | null {
  let best: TextBlock | null = null;
  let bestDistance = Infinity;

  for (const block of blocks) {
    // The header sometimes reads with trailing OCR noise (e.g. "CHARACTER G" or
    // "CHARACTER O M" -- observed in Phase 0's raw output). Compare only the
    // leading token against "character".
    const firstWord = block.text.trim().split(/\s+/)[0]?.toLowerCase() ?? "";
    const distance = levenshtein(firstWord, ANCHOR_TEXT);
    if (distance < bestDistance) {
      bestDistance = distance;
      best = block;
    }
  }

  return bestDistance <= MAX_EDIT_DISTANCE ? best : null;
}
```

// voting.ts
export function createFieldVoter(opts: { windowSize: number; threshold: number }) {
  const window: string[] = [];
  let locked: string | null = null;

  return {
    vote(candidate: string | undefined) {
      if (locked != null || candidate == null) return;
      window.push(candidate);
      if (window.length > opts.windowSize) window.shift();

      const counts = new Map<string, number>();
      for (const v of window) counts.set(v, (counts.get(v) ?? 0) + 1);
      for (const [value, count] of counts) {
        if (count >= opts.threshold) {
          locked = value;
          break;
        }
      }
    },
    getLocked(): string | null {
      return locked;
    },
  };
}
```

**Step 2: Build the scan screen's state**

In `scan.tsx`, three `createFieldVoter` instances (one per field, using
`scannerConfig.lockThresholds` and `scannerConfig.voteWindowSize`), fed by
`useTextScanner`'s callback: run each frame's blocks through `findAnchor` +
`extractFields`, then `.vote(...)` each field. Render each field's current best
guess (from the voter's internal window, not just the locked value) greyed out
until locked, solid once `getLocked()` returns non-null. Also render a simple
rectangle overlay near screen center as a rough aiming guide (visual only --
doesn't crop anything, just tells the user roughly where to point).

Match the perceived-speed design intent from the design doc: candidates render
from the first frame, not after some silent delay.
